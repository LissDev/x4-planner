# X4 9.0 ship data provenance

`ship-data.js` is generated from the locally installed X4 Foundations 9.0.0.0 game files. The extractor reads base `01.cat`–`09.cat` with matching `.dat` files and the `ext_*.cat`/`.dat` pairs in exactly these official extensions: `ego_dlc_split`, `ego_dlc_terran`, `ego_dlc_boron`, `ego_dlc_mini_01`, `ego_dlc_mini_02`, `ego_dlc_pirate`, and `ego_dlc_timelines`. The game files are read only; other extensions are excluded. The source fingerprint comes from those CAT indexes. This is a generated data file, so the generated-files exception to the repository's test-first rule applies.

`libraries/wares.xml` supplies player-buildable ware IDs, price ranges, and build recipes. Ship and equipment macros under `assets/*/macros/` supply hull, cargo, physics, thrust, shield, weapon, projectile, and ammunition properties. Component XML supplies ship slot and equipment connection tags. `t/0001-l007.xml` supplies Russian names, with the game's English text as fallback. The extractor applies official `<diff>` records in archive order, verifies CAT entry MD5 hashes, and fails on unresolved patches or unknown referenced build materials/projectiles.

From this directory, regenerate and check byte-for-byte reproducibility with the commands below. Replace `<X4_INSTALL_DIRECTORY>` with your X4 installation folder, keeping the quotes around the path:

```powershell
python scripts/extract-ships.py --game '<X4_INSTALL_DIRECTORY>' --output ship-data.js
python scripts/extract-ships.py --game '<X4_INSTALL_DIRECTORY>' --check ship-data.js
```

`globalThis.X4_SHIP_DATA` contains 232 ships, 478 equipment records, and 17 construction wares from this installation. Each ship includes raw hull, cargo, mass, drag, inertia, acceleration factors, thruster tags, missile capacity, prices, build options, and slot groups. Equipment includes engines, shields, weapons, turrets, missile launchers, ammunition, and thrusters. A `buildOptions` entry gives a method, build time, and a material ware-to-quantity map. `priceMin`, `priceAverage`, and `priceMax` are the source ware prices in credits; build cost is the sum of selected material quantities multiplied by material prices.

Physical ship slot groups record the original connection tags and count. Thrusters are selected through a virtual ship macro `<thruster tags="size">` property rather than a physical component slot. The extractor adds one `thruster:virtual` group per ship and matches its size tag against each thruster component's `thruster size component` connection. `compatibleEquipmentIds` matches equipment mount class, size, and subtype tags; standard equipment is accepted on advanced mounts. Launcher `compatibleAmmoIds` matches game ammunition and missile tags. These lists represent player-buildable equipment in the extracted catalog. Eight special connection slots on `ship_gen_m_corvette_02` (Envoy) have no player-buildable match and carry `compatibilityStatus: "no-player-buildable-equipment-match"`.

Equipment `stats` preserves available raw game XML attributes, including thrust/boost/travel, shield recharge, weapon heat/reload/ammunition, projectile damage, area damage, bullet speed/lifetime, missile properties, and relevant physics. There is no fixed ship speed: it depends on the chosen engines and the ship's drag. The unused derived `burstDps` remains `null` with `derivedStatsStatus`; nominal rates are calculated where source projectile values establish them. Raw values alone do not establish every in-game heat, reload, beam, ammunition, or out-of-sector combat rule. The application labels estimates rather than presenting them as exact game stats.

Two source price records violate min ≤ average ≤ max and are preserved exactly with `priceAnomaly: true`: `shield_spl_m_standard_02_mk1` has a raw minimum of 1,536,515,365 versus an average of 17,072 in `ego_dlc_split/ext_03.dat` `libraries/wares.xml`; `ship_bor_m_miner_solid_01_a` has a raw minimum of 12,142,835 versus an average of 172,090 in `ego_dlc_boron/ext_03.dat` `libraries/wares.xml`. Three racer ships have cargo capacity zero in the source. Some translation records prepend a parenthesized alternate name with escaped parentheses; the extractor removes that wrapper before resolving the Russian name, retaining meaningful qualifiers such as `(Газ)`. Consumers should default to the average price unless the user selects another range and should display anomalies when relevant.

Validation checks unique IDs, well-formed Russian names, finite nonnegative prices, positive build quantities and times, material and ammunition references, ship physics and slot consistency, a compatible thruster choice for every ship, and representative Osprey, Nemesis, pulse laser, beam, flak, and missile records. The extraction command reports zero unresolved patches and zero skipped records.
