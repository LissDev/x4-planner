# X4 Planner

[English instructions](README.md)

Локальный планировщик станций и кораблей на данных X4: Foundations 9.0 и официальных дополнений. Помогает подобрать производственную цепочку, оценить стоимость и доход станции, оснастить корабли и сравнить сборки. Интерфейс поддерживает русский и английский языки; при первом запуске выбран английский. Язык меняется в шапке приложения.

## Запуск в Windows через Docker Desktop

Для запуска готового планировщика не нужны Node.js, Python или установленная X4.

1. Установите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/), следуя инструкциям установщика. Перезагрузите Windows, если потребуется.
2. Запустите Docker Desktop и дождитесь запуска его движка. Нужны Linux-контейнеры (режим по умолчанию); при необходимости переключитесь на них через меню Docker в системном трее.
3. На [странице репозитория](https://github.com/LissDev/x4-planner) выберите **Code → Download ZIP**. Распакуйте архив, откройте папку с файлом `Dockerfile` и выберите **Открыть в Терминале** в контекстном меню папки. Команды ниже подходят для PowerShell.
4. Соберите образ. Первая сборка загружает зависимости и требует интернета:

   ```powershell
   docker build -t x4-planner .
   ```

5. Запустите планировщик:

   ```powershell
   docker run --rm --name x4-planner -p 127.0.0.1:8765:80 x4-planner
   ```

6. Оставьте терминал открытым и перейдите в браузере по адресу [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Адрес доступен только с вашего компьютера. После сборки планировщик работает без интернета.

Для остановки нажмите **Ctrl+C** в этом терминале либо выполните `docker stop x4-planner` в другом. Контейнер удалится автоматически. Для повторного запуска повторите шаг 5. Если Docker сообщает об отсутствии движка или ошибке подключения, запустите Docker Desktop и дождитесь готовности движка. Если порт 8765 занят, замените привязку на `127.0.0.1:8766:80` и откройте в браузере порт 8766.

Для обновления сначала экспортируйте сохранённые проекты и сборки, скачайте и распакуйте новый ZIP, остановите контейнер и повторите шаги 4–6 из новой папки. Обновите страницу в браузере. Используйте тот же браузер и адрес, чтобы видеть прежние сохранения.

## Первая станция или корабль

- **Станции:** создайте проект, выберите конечные товары и количество модулей, нажмите **Построить цепочку** для просмотра цепи с минимальной стоимостью строительства. **Применить** меняет черновик, **Отмена** оставляет его без изменений. **Использовать резерв** добавляет конечные модули за счёт имеющегося производства полуфабрикатов и разрешённых внешних поставок. Затем нажмите **Сохранить проект**.
- Можно вручную добавлять модули, выбирать рецепты и расы, менять цены и солнечный свет (100 означает 100%), разрешать закупку ресурсов или собственное бесплатное внешнее снабжение. Автоматизация работников добавляет жильё, пищу и медикаменты; автоматические хранилища покрывают часовые потоки грузов. Стоимость строительства, часовые потоки и доход пересчитываются по черновику.
- **Корабли:** создайте именованную сборку, выберите корабль и совместимое оборудование, нажмите **Сохранить сборку**. В разделе **Сравнить сборки** можно сопоставить две сохранённые сборки для одного размера цели. Показатели оружия приблизительные; учитывайте указанные рядом допущения и отметки о неполных или неизвестных данных.

## Сохранения и резервные копии

Проекты и сборки хранятся в `localStorage` вашего браузера, а не в Docker или на сервере. Изменения записываются только после **Сохранить проект** или **Сохранить сборку**. Экспортируйте каждый сохранённый объект в JSON из соответствующего списка. Для восстановления используйте **Импорт JSON** в разделе станций или кораблей. Импорт проверяет файл и запрашивает подтверждение перед заменой объекта с тем же идентификатором.

Храните резервные копии вне папки исходников. Очистка данных браузера, приватное окно, другой браузер/профиль или другой адрес могут сделать сохранения недоступными. У `localhost` и `127.0.0.1`, разных портов и прямого открытия `index.html` разные контексты хранения. Для переноса экспортируйте JSON по старому адресу и импортируйте по новому. Пересборка или удаление контейнера сами по себе не удаляют сохранения браузера. Облачной синхронизации и связи с сохранениями X4 нет.

## Возможности и ограничения

- Расчёт станции оценивает производство, обеспечение работников, материалы строительства и денежные потоки. Геометрия модулей, доступность чертежей, корабельная логистика, реальные запасы и очередность строительства не моделируются. Оценка прибыли предполагает доступность указанных закупок и продаж.
- В каталоге есть 18 официальных производственных и ремонтных отсеков для S/M, L и XL. Их материалы входят в стоимость станции; строительство и ремонт кораблей, доход верфи, её рабочие и эксплуатационное снабжение не моделируются.
- Урон — оценка приложения, а не нативная формула боя X4. Оценка вне сектора использует допущения о размере цели. Отдельный расчёт непрерывного огня в секторе учитывает поддерживаемые параметры перезарядки, магазина и нагрева, но не устанавливает точное поведение игры. При нехватке данных результат неизвестный или частичный; ракеты и боезапас показаны отдельно. Дальность, геометрия попаданий и все нативные взаимодействия не моделируются.
- Данные относятся к извлечённой версии игры и официальным дополнениям, а не модификациям или последующим обновлениям. Источники и команды повторного извлечения описаны в [DATA-SOURCES.md](DATA-SOURCES.md) и [SHIP-DATA-SOURCES.md](SHIP-DATA-SOURCES.md).

## Прямой запуск и разработка

Для прямого запуска без сети откройте `index.html` в современном браузере. Рядом должны оставаться `styles.css`, `station-v2.css`, `bundle.js`, `data.js` и `ship-data.js`. Если ограничения локальных файлов мешают работе, используйте Docker по инструкции выше.

Для изменения исходников установите актуальную версию Node.js с поддержкой `node --test --test-isolation=none` (сборка Docker использует Node 22), затем выполните из папки проекта:

```powershell
npm ci
npm test
npm run build
```

Редактируйте `src/` и пересобирайте `bundle.js`. Необязательная команда `npm run host-check` проверяет интерфейс в установленном Edge; путь к другому поддерживаемому браузеру можно задать в `X4_BROWSER`. Проверки создают локальные файлы в `qa/`.

Общая лицензия проекта не задана. Источники игровых каталогов указаны отдельно; лицензия решателя не распространяется на эти каталоги.
